# Evade Films

Онлайн-кинотеатр на Next.js: каталог фильмов и сериалов, страницы тайтлов и
просмотр через [EvadePlayer](https://github.com/evadepw/evade-player).

Интерфейс собран по дизайн-системе **Evade Films** — тёмная, полностью
монохромная, нарочито пустая: матовый чёрный «зал», в котором единственный
источник цвета — обложка фильма.

Что изменилось от версии к версии — в [CHANGELOG.md](CHANGELOG.md).

## Запуск

```bash
cp .env.example .env.local   # укажите адрес каталога API
npm install
npm run dev
```

Бэкенд бывает недоступен — тогда фронт поднимается на фикстурах:

```bash
npm run dev:mock
```

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_API_URL` | Origin каталога (`http://host:8000`), без `/api/v1`. Читается на сборке: из него собираются список разрешённых хостов картинок и прокси `/api/*`. Браузер по этому адресу не ходит. |
| `API_URL` | Необязательный origin для серверного рендера, если контейнер ходит в API по другому адресу. |
| `NEXT_PUBLIC_IMAGE_HOSTS` | Дополнительные хосты для `<Image>`, через запятую. Хост API добавляется сам. |
| `NEXT_PUBLIC_API_TIMEOUT` | Таймаут запроса, мс (по умолчанию 8000). |
| `IMAGES_ALLOW_LOCAL_IP` | `true` — снять SSRF-защиту оптимизатора картинок. Нужно только когда медиа отдаётся с приватного адреса, который вы контролируете. |
| `NEXT_PUBLIC_API_MOCK` | `true` — отдавать каталог из фикстур вместо сети. Ставится скриптом `dev:mock`; в задеплоенной среде включать нельзя. |

Скрипты: `dev`, `build`, `start`, `lint`, `typecheck`, `vendor:player`.

### Docker

```bash
cp .env.example .env.production   # адрес каталога API — как его видно из контейнера
docker compose up --build
```

Сайт поднимается на `http://localhost:3000`.

Образ **собирается из `.env.production`**, а не просто запускается с ним:
`next build` вшивает `NEXT_PUBLIC_*` в браузерный бандл и замораживает в выводе
сборки список хостов картинок и адрес прокси `/api/*`. Поэтому файл нужен в
контексте сборки, и после его правки образ надо пересобрать (`--build`).
`.dockerignore` пропускает внутрь только его: `.env.local` в приоритете Next
стоит выше `.env.production` и иначе молча победил бы внутри образа.

`NEXT_PUBLIC_API_URL` должен резолвиться **изнутри контейнера** — туда ходят
серверный рендер и оптимизатор картинок. Когда бэкенд живёт на хост-машине, это
`http://host.docker.internal:8000` (на Linux адрес добавляет `extra_hosts` в
compose); когда соседним сервисом — его имя в сети compose.

Сборка идёт в три стадии: `npm ci`, `next build` и рантайм из
`output: "standalone"` — трассировка тянет в финальный образ только те
`node_modules`, до которых сервер реально дотягивается (~300 МБ). `public` и
`.next/static` standalone исключает, рассчитывая на CDN; здесь его нет, поэтому
Dockerfile кладёт их обратно и раздаёт сам сервер.

## Архитектура

```
src/
├── app/                     маршруты (App Router)
│   ├── movies/[id]/watch/   плеер фильма
│   ├── series/[id]/watch/   плеер сериала
│   ├── account/             профиль, закладки, оценки, комментарии, история
│   └── users/[username]/    публичная карточка пользователя
├── components/
│   ├── ui/                  shadcn-примитивы, перенастроенные на токены Evade
│   ├── media/               Poster, PosterCard, ProgressBar
│   ├── catalog/             Rail, Hero, сетки, фильтры, поиск
│   ├── auth/                диалог входа, меню аккаунта, гейт для /account
│   ├── interactions/        оценка, закладки, комментарии, строка контента
│   ├── account/             формы профиля и списки /me/
│   ├── layout/              шапка, подвал, секции
│   ├── feedback/            пустые состояния и ошибки
│   └── player/              обёртки над EvadePlayer
├── lib/
│   ├── api/                 http (axios), endpoints, DTO, сервисы, ключи кэша
│   ├── domain/              модели предметной области и мапперы
│   ├── i18n/                словарь UI и разбор переводов бэкенда
│   ├── format.ts            метаданные, длительности, таймкоды
│   └── routes.ts            таблица маршрутов
├── hooks/                   клиентские хуки данных (React Query)
├── providers/               QueryProvider, AuthProvider
└── styles/tokens.css        токены дизайн-системы
```

Слои сверху вниз: **страница → компонент → сервис → http**. Правила, которые
держат это в порядке:

- **DTO не выходят за `lib/api`.** Сервисы возвращают доменные модели
  (`TitleSummary`, `TitleDetail`, `SeriesPlayback`), поэтому переименование поля
  в бэкенде — правка в `types.ts` и маппере, и больше нигде.
- **Фильмы и сериалы — один тип `TitleSummary` с полем `kind`.** Rail, сетка и
  карточка написаны один раз и работают для обоих.
- **URL — источник состояния списка.** Фильтры и поисковый запрос живут в
  query-параметрах: ссылка на отфильтрованный каталог шарится, «назад» работает,
  а React Query кэширует по тем же параметрам.
- **Ошибки нормализованы в `ApiError`.** 404 (в том числе черновики, которые
  бэкенд прячет от анонимов) превращается в `notFound()`, остальное всплывает в
  `error.tsx`.
- **Структуру держат волосяные линии, а не блоки.** У системы один тон и нет
  иллюстраций, поэтому взгляду не за что зацепиться, если секции ничем не
  разделены. `SectionHeader` даёт каждой секции надзаголовок, счётчик и линию
  снизу — это разница между «минималистично» и «пусто». Плашек, теней и рамок
  вокруг контента по-прежнему нет.
- **Пустых экранов нет.** Поиск без запроса показывает весь каталог, страница
  тайтла — раздел «Похожее», страница просмотра — список эпизодов и синопсис.
  Состояние-заглушка остаётся только там, где данных действительно нет. Рейл
  «Продолжить просмотр» не рисует ни скелет, ни заглушку: если истории нет, его
  просто нет.
- **Сессия не пересекает границу сервера.** Токен лежит в браузере, поэтому всё
  личное — оценки, закладки, комментарии, прогресс — это клиентские островки на
  серверных страницах. Подробности в разделе «Аккаунт».
- **Токены — единственный источник стилей.** `styles/tokens.css` перенесён из
  дизайн-системы дословно; `globals.css` только раскладывает их по неймспейсам
  Tailwind и по семантическим переменным shadcn, поэтому все примитивы
  (`Button`, `Select`, `Dialog`) сразу в брендовой палитре.

### Данные

Серверные компоненты вызывают `catalogService` напрямую — первый экран приходит
уже отрендеренным. React Query подхватывает то, что зависит от действий
пользователя: фильтры каталога, «показать ещё», поиск, переключение озвучки.

Ссылки на манифесты подписанные и короткоживущие, поэтому страницы просмотра
помечены `dynamic = "force-dynamic"`, а playback-запросы не кэшируются
(`staleTime: 0`). Для сериала используется `playback-batch`: один запрос отдаёт
подписанные манифесты для всех эпизодов и озвучек, и переключение серии внутри
плеера не ждёт сеть.

Таймаут HTTP намеренно короткий: серверный компонент ждёт ответ прямо в рендере,
и зависший API держит открытым весь RSC-поток — страница отрисуется, но не
станет интерактивной. Лучше быстро упасть в состояние ошибки с кнопкой
«Повторить».

### Прокси до API

Браузер не обращается к бэкенду напрямую: запросы уходят на origin самого
приложения, а `next.config.ts` переписывает `/api/*` на адрес каталога.

Так сделано потому, что каталог не отдаёт CORS-заголовков. Пока в API ходил
только сервер, это не проявлялось — а всё, что связано с аккаунтом, работает из
браузера, и первый же клиентский запрос упёрся в
`No 'Access-Control-Allow-Origin'`. Просить бэкенд перечислить фронтовые origin'ы
хуже: список пришлось бы поддерживать для каждого окружения и не забывать при
каждом деплое. Здесь браузер всегда разговаривает с тем же origin, с которого
загрузился, а заголовок `Authorization` проходит через переписывание нетронутым.

Две детали, без которых это не работает:

- **Слэш на конце обязателен.** DRF отвечает только на пути со слэшем
  (`APPEND_SLASH`), а Next по умолчанию сначала редиректит такие адреса на
  версию без слэша — до того, как дойдёт до rewrite. Поэтому автоматический
  редирект выключен (`skipTrailingSlashRedirect`) и возвращён обратно правилом
  в `redirects()` для всего, кроме `/api`.
- **Правил переписывания два.** `:path*` захватывает только сегменты и съедает
  завершающий слэш, поэтому первое правило добавляет его обратно — иначе Django
  отвечает 301, и браузер уходит на origin бэкенда, то есть снова в CORS.

Серверный рендер ходит в API напрямую: гонять запрос через собственный сервер
незачем.

### Аккаунт

Схема отдаёт JWT (`jwtAuth` рядом с прежними `basic` и `cookie`), и сессия живёт
**только в браузере** — `lib/api/tokens.ts`, `localStorage`. Причина в том, что
axios-инстанс один на процесс: токен, положенный на него во время RSC-рендера,
достался бы следующему посетителю. Поэтому серверные компоненты по-прежнему
ходят в каталог анонимно, а всё, что зависит от того, кто смотрит, — клиентские
островки: `RatingControl`, `WatchlistButton`, `CommentsSection`,
`ContinueWatchingRail`, страницы `/account`.

Как это устроено:

- `AuthProvider` читает хранилище через `useSyncExternalStore`, а источником
  правды считает `/auth/me/`, а не содержимое токена: сохранённый токен бывает
  протухшим, отозванным или принадлежит аккаунту, которому с тех пор закрыли
  комментарии.
- Access-токен короткоживущий, поэтому 401 — рядовой случай: интерцептор в
  `http.ts` один раз обновляет пару через `/auth/refresh/` и повторяет запрос.
  Обновление single-flight: страница с пятью запросами иначе сожгла бы пять
  refresh-токенов, и при включённой ротации четыре вернулись бы невалидными.
- Выход всегда локальный: refresh уходит в блэклист, но даже если запрос не
  дошёл, токены стираются — сетевая ошибка не должна оставлять чужую сессию
  открытой.
- При смене аккаунта кэш React Query не инвалидируется, а вычищается: ключи
  личных запросов не содержат id пользователя, и остаток от прошлой сессии
  показался бы следующей.

Каталог отдаёт агрегаты (`rating_avg`, `rating_count`, `comment_count`,
`views_count`) прямо в списках и на детальной странице, поэтому оценка на
карточке не стоит запроса на плитку, а блок оценки на странице тайтла рисует
среднее сразу и дожидается сети только ради гистограммы и «вашей оценки».

Взаимодействия висят на трёх типах контента, и пропуски в схеме подняты в типы:
`ShelvableType` — фильм и сериал (эпизод откладывают через сериал),
`ResumableType` — фильм и эпизод (у сериала нет своей точки возврата). Вызов,
для которого у бэкенда нет маршрута, не компилируется.

Прогресс и просмотры пишет сам плеер: EvadePlayer сохраняет состояние каждые
пять секунд, на паузе и перед выгрузкой, а `usePlaybackTracking` пересылает это
в `PUT …/progress/`. Длительность плеер не сообщает — её читают с `<video>`,
потому что без неё бэкенд не выведет проценты. Просмотр засчитывается на первом
сохранении, а не при открытии страницы: так счётчик означает «смотрели», а не
«зашли».

### Мок-режим

`NEXT_PUBLIC_API_MOCK=true` подменяет **адаптер axios**, а не сервисы. Это
намеренно самый нижний слой: те же DTO, те же мапперы, та же пагинация и те же
404 — фикстуры проходят ровно тот путь, что и реальные ответы, поэтому на моках
нельзя случайно «починить» то, что сломано с живым бэкендом.

Реализовано в `lib/api/mock/`: `fixtures.ts` — данные в проводном формате
(часть тайтлов без постера, без длительности и без английского перевода — так
выглядит настоящий каталог), `adapter.ts` — маршрутизация, методы, фильтры,
поиск, сортировка и постраничная выдача, `state.ts` — изменяемая часть.
Плейсхолдеры обложек лежат в `public/mock/`, а playback отдаёт публичный
тестовый HLS-поток, так что плеер в мок-режиме реально играет.

Каталог статичен, потому что его наполняют не здесь. Аккаунты, оценки,
комментарии, закладки и прогресс — нет: это ровно то, что фронт **пишет**, и
мок, умеющий только читать, оставил бы половину приложения непроверенной. Он
воспроизводит и отказы, которые UI обязан обрабатывать: 401 (и следующий за ним
refresh), 403 на чужой комментарий, 400 с ошибками по полям.

Состояние зеркалится в `sessionStorage`, иначе полная перезагрузка страницы
выкидывала бы из аккаунта. Вкладку закрыли — сброс. При старте мок засевает двух
пользователей (`masha@evade.local` и `igor@evade.local`, пароль `evade-demo`),
их оценки и ветку комментариев: пустой тред не проверяет вёрстку, которая должна
пережить настоящие данные. Отсюда же работает `/users/masha` — эта страница
рендерится на сервере, а серверная половина мока браузерного хранилища не видит,
и резолвятся там только засеянные аккаунты.

Режим включается только явно и никогда не выводится из неудачного запроса:
незаметно замоканный прод хуже видимой аварии.

### Плеер

EvadePlayer подключён как веб-компонент `<evade-player>`, а не как React-экспорт
пакета: React-сборка `evade-player@0.2.1` инлайнит react-dom за `require()`-шимом,
который Turbopack выполнить не может. Standalone-сборка такого шима не содержит,
но не опубликована в `exports`, поэтому она копируется из `node_modules` в
`public/vendor/evade-player/` на `postinstall` (`scripts/vendor-player.mjs`) и
подгружается скриптом только на маршрутах просмотра. Ничего не тянется с CDN.

React-обёртка `components/player/video-player.tsx` присваивает сложные значения
свойствами элемента и превращает его CustomEvent'ы в обычные колбэки.

## Что осталось за кадром

- Бэкенд отдаёт `primary_color` / `accent_color`; система принципиально
  монохромная, поэтому они читаются, но не применяются.
- Шрифты — ближайшие аналоги из Google Fonts (Unbounded / Manrope / JetBrains
  Mono) с полной кириллицей: фирменных файлов в дизайн-системе не было. Замена —
  правка трёх объявлений в `app/layout.tsx`.
- Аватар пользователя можно только показать: схема отдаёт `avatar` на чтение, а
  загрузки файла в ней нет.
- Комментарии не обновляются в реальном времени. Схема даёт только опрос, а
  тянуть тред по таймеру ради редкой активности — плохой размен.
- Эпизоды не откладывают в закладки, а сериалы не хранят точку возврата: так в
  схеме, и UI это повторяет, а не обходит.
